# PostgreSQL: начальная интеграция

Добавлены SQLAlchemy AsyncEngine, psycopg 3, сессии на запрос и Alembic.
Схема источников, документов, версий и ИИ-результатов добавлена миграцией
0002_ingestion_store; описание в [WIKI.md](WIKI.md). Персональные задания
и профили студентов пока не создаются. Первая ревизия фиксирует начало истории.

## Настройка

`HSE_DATABASE_URL` задаётся в окружении сервера или в локальном `.env`.
Поддерживаются `postgresql://` и `postgresql+psycopg://`; используется psycopg 3.
Пример формы URL (замените пароль своим значением):

~~~dotenv
HSE_DATABASE_URL=postgresql+psycopg://hse_agent:<url-encoded-password>@127.0.0.1:5432/hse_agent
~~~

Специальные символы в пароле внутри URL должны быть percent-encoded.
Параметры URL, включая `sslmode`, сохраняются. Приложение не меняет настройки TLS.
URL не включается в HTTP-ответы, repr настроек и сообщения валидации.

Необязательные настройки:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| HSE_DATABASE_URL | не задана | Подключение к PostgreSQL |
| HSE_DB_POOL_SIZE | 5 | Максимум соединений одного процесса, без overflow |
| HSE_DB_CONNECT_TIMEOUT | 5 | Таймаут подключения и ожидания пула, секунды |

Без URL сайт и демонстрационные данные доступны. При заданном URL engine
создаётся при старте приложения и освобождается при остановке; реальное
соединение устанавливается при первом запросе к БД.

## Локальная БД для разработки

Установите Docker, скопируйте `.env.example` в `.env` и задайте
`POSTGRES_PASSWORD`, а также соответствующий `HSE_DATABASE_URL`.
Для файла `compose.db.yaml` имя БД и пользователь по умолчанию — `hse_agent`.
`POSTGRES_PORT` позволяет поменять локальный порт; он должен совпадать с URL.

~~~sh
docker compose -f compose.db.yaml up -d --wait
uv sync --frozen
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
~~~

PostgreSQL 17 слушает только 127.0.0.1, данные находятся в именованном volume.
Остановка с сохранением данных:
`docker compose -f compose.db.yaml down`.
Файл предназначен для локальной БД и не заменяет конфигурацию развёртывания.
Внутри контейнера приложения адрес 127.0.0.1 указывает на сам контейнер;
для серверной БД указывайте адрес, доступный именно приложению.

## HTTP-проверки

- `GET /api/v1/health` — прежняя liveness-проверка HTTP-приложения.
- `GET /api/v1/ready` — реальный `SELECT 1` в PostgreSQL.
  Успех: 200 и `{"status":"ready","database":"connected"}`.
- URL не задан: 503 с `error.code=database_not_configured`.
- БД недоступна или проверка превысила таймаут: 503 с
  `error.code=database_unavailable` и `retryable=true`.

Readiness проверяет доступность БД, но не актуальность миграций.
Доступность PostgreSQL не означает, что задания уже сохраняются в БД
или что подключены университетские источники.

## Сессии и миграции

Для обработчика FastAPI используйте зависимость `app.db.session.get_session`.
Сервисы и фоновые задачи могут использовать `Database.session()`.
Каждому запросу или фоновой задаче нужна своя сессия.
Транзакции фиксируются явно в сервисах через `session.begin()` или
`await session.commit()`. Выход без commit и исключения откатывают изменения.

~~~sh
uv run alembic current
uv run alembic upgrade head
uv run alembic revision --autogenerate -m "Describe schema change"
~~~

Будущие модели наследуют `app.db.base.Base`; импортируйте их в
`migrations/env.py` перед autogenerate. Проверяйте сгенерированную миграцию.
Приложение не вызывает `create_all()` и не запускает миграции при каждом старте.
Обновление схемы — отдельный шаг перед запуском новой версии приложения.
Dockerfile включает Alembic и миграции, команда в образе:
`python -m alembic upgrade head`.

## Проверки

`uv run pytest` проверяет необязательность БД, ошибочную конфигурацию,
недоступное соединение, liveness и отсутствие пароля в ответах об ошибках.

Для настоящих интеграционных тестов задайте `HSE_TEST_DATABASE_URL`,
указывающий на отдельную пустую БД с именем, оканчивающимся на `_test`:

~~~sh
uv run pytest -m integration -v
~~~

Тестовая БД должна быть отдельной и пустой: тесты могут очищать таблицы приложения.
Тесты выполняют upgrade/downgrade/upgrade, проверяют реальную запись,
commit и rollback, сохранность после переподключения и HTTP readiness.
Они создают и удаляют только свою служебную таблицу с уникальным именем
и изменяют историю Alembic в тестовой БД. Без переменной эти тесты пропускаются.
В GitHub Actions отдельный PostgreSQL 17 создаётся автоматически, и полный
набор тестов выполняется с настоящей БД.
