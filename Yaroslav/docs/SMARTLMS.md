# SmartLMS (edu.hse.ru)

SmartLMS ВШЭ работает на Moodle, и на нём включён веб-сервис мобильного приложения
(`enablemobilewebservice: 1` в публичной конфигурации). Агент читает через него
календарь дедлайнов студента по личному ключу. Ключ студент берёт сам после входа
через ЕЛК, пароль агенту не нужен.

## Подключение по ссылке календаря (рекомендуется)

Работает у студентов ВШЭ: нужна только личная ссылка экспорта календаря Moodle,
без пароля и без ключа API.

1. Откройте https://edu.hse.ru/calendar/export.php (или «Календарь» → «Экспорт календаря»).
2. Выберите «Все события» и «Недавние и следующие 60 дней», нажмите
   «Получить адрес календаря».
3. Скопируйте ссылку вида
   `https://edu.hse.ru/calendar/export_execute.php?userid=...&authtoken=...`
   и впишите в `.env`: `HSE_SMARTLMS_CALENDAR_URL=<ссылка>`.
   В ссылке личный ключ: не публикуйте её. Принимаются только HTTPS-адреса edu.hse.ru.
4. Проверьте:

   ~~~sh
   .\.venv\Scripts\python.exe -m app.smartlms check
   ~~~

   В ответе будет `"mode": "calendar"`, число дедлайнов и ближайшие из них.

Особенности календаря: дата без времени хранится как дата, а не как 23:59. Перенос
срока обновляет то же событие (по UID) и попадает в историю. Сданное задание из
календаря Moodle не исчезает, поэтому его пока нужно отмечать «Готово» на сайте.
Если задан и `HSE_SMARTLMS_TOKEN`, используется API: он точнее.

## Подключение по ключу API (у студентов ВШЭ закрыто)

У студентов ВШЭ пустая страница «Ключи безопасности», а вход приложения через браузер
(`launch.php`) выключен: «Не включен или не настроен плагин». В SmartLMS ВШЭ включён
тип входа «через приложение», то есть по логину и паролю на `login/token.php`. Этим же
способом входит официальное мобильное приложение Moodle.

1. Запустите и введите логин ЕЛК и пароль. Пароль скрыт при вводе, уходит только на
   edu.hse.ru по HTTPS и нигде не сохраняется:

   ~~~sh
   .\.venv\Scripts\python.exe -m app.smartlms login
   ~~~

2. Команда проверит ключ, запишет его в `.env` как `HSE_SMARTLMS_TOKEN` и выведет ваше
   имя из SmartLMS. `smartlms_invalid_login` значит, что SmartLMS не принял логин
   или пароль ЕЛК напрямую. Для аккаунтов с входом через ЕЛК такое возможно, и тогда
   этот способ недоступен.
3. Проверьте дедлайны без записи в базу:

   ~~~sh
   .\.venv\Scripts\python.exe -m app.smartlms check
   ~~~

`login --browser` — вход через `launch.php` с ключом из консоли браузера. Это
запасной вариант на случай, если ВШЭ включит вход через браузер.

Ключ даёт тот же доступ, что и мобильное приложение. Не публикуйте его. Сбросить
ключ можно на той же странице.

## Как работает

- `core_calendar_get_action_events_by_timesort` возвращает задания, тесты и другие
  активности со сроком. Окно: 7 дней назад и 60 дней вперёд
  (`HSE_SMARTLMS_LOOKBACK_DAYS`, `HSE_SMARTLMS_LOOKAHEAD_DAYS`).
- Каждое событие хранится как документ `deadline:<модуль>:<экземпляр>`. Если
  преподаватель перенёс срок, обновляется та же запись, а прежний срок остаётся
  в истории. На экране «Задания» показывается «Источник изменил срок».
- Время берётся из Moodle точно (unix-время) и показывается в `HSE_TIMEZONE`.
- Календарь действий — полный снимок окна. Сданное задание Moodle из него убирает,
  поэтому запись становится неактивной и пропадает из заданий.
- `smartlms-worker` в Compose синхронизирует каждые 15 минут, при ошибках делает
  повторы с паузой. Без ключа воркер ничего не пишет в базу.
- Ручной проход: `python -m app.smartlms sync`.
- Дедлайны SmartLMS не отправляются в OpenAI: данные уже структурированы.
