# Контракт и передача фронтенда

## Запуск и границы

Сайт: http://127.0.0.1:8000. Swagger UI: http://127.0.0.1:8000/docs.
Снимок схемы для команды: [openapi.json](openapi.json).
Схема генерируется из Python-моделей и маршрутов; редактировать её вручную не нужно.

Разметка, стили и JS находятся в `frontend/`. Они не импортируют Python-код.
Весь доступ к данным сосредоточен в `frontend/static/js/api.js`.
Бэкенд может менять коннекторы и сервисы, сохраняя этот контракт.

## API первой версии

| Метод и путь | Результат |
| --- | --- |
| GET /api/v1/dashboard | Объект `meta`, `tasks`, `sources`, `plan` |
| GET /api/v1/health | Состояние HTTP-приложения, версия и режим данных |
| GET /api/v1/ready | 200 при доступном PostgreSQL; 503, если БД не настроена или недоступна |
| GET /api/v1/sources | Подключённые источники, объём материалов и результаты синхронизации |
| GET /api/v1/documents | Библиотека реальных страниц с пагинацией |
| GET /api/v1/documents/{id} | Текст страницы, версия, ссылки и сохранённый анализ |
| GET /api/v1/knowledge/summary | Последняя сохранённая сводка, без вызова модели при чтении |
| GET /openapi.json | Актуальная машиночитаемая схема |

Вики ФКН автоматически обновляется серверным worker и сохраняется в PostgreSQL;
извлечение и сводка OpenAI кешируются. Чтение перечисленных API не вызывает модель.
Операторский POST /api/v1/integrations/wiki/sync запускает только загрузку;
требует серверный X-Ingestion-Token и не предназначен для браузерного кода.
Авторизация пользователей, назначение кандидатов из вики студенту, запись
изменений заданий и отправка напоминаний ещё не реализованы.
Health проверяет только HTTP-приложение; ready — доступность PostgreSQL.
Настройки БД и коды ошибок readiness описаны в [POSTGRESQL.md](POSTGRESQL.md).
Фронтенду для работы с демонстрационными данными PostgreSQL не требуется.

### Явный источник «Фейк-данные»

`GET /api/v1/dashboard?data_source=fake` возвращает изолированные вымышленные
задания, четыре материала и план относительно текущей даты в часовом поясе сервера.
Он доступен и при `HSE_DEMO_MODE=false`; обычный запрос без этого параметра
сохраняет прежнее поведение. Источник имеет ID `fake`, `meta.mode=demo`,
а обязательное уведомление явно сообщает о вымышленных данных. Запрос не читает
DSBA или PostgreSQL и ничего туда не записывает.

`available_minutes=0..720` задаёт бюджет плана (по умолчанию 120).
`completed` содержит ID выполненных задач через запятую. План исключает их,
не выходит за бюджет и конец текущего дня; не поместившиеся задачи остаются
в `unscheduled_task_ids`. ID задач включают дату, чтобы вчерашние локальные
отметки не скрывали сегодняшний пример. Перенесённый срок содержит
`previous_due_at` вместе с текущим `due_at` и объяснением `deadline_changed`.
Ссылки `/demo/materials/{slug}` ведут на явно помеченные учебные страницы.
Этот источник демонстрирует интерфейс и не заменяет живые подключения MVP.

### Поля ответа

- `meta.mode`: `demo` — учебные примеры; `unconfigured` — примеры отключены,
  реальных материалов нет; `live` — есть реальные сохранённые материалы.
  `live` не означает, что все источники подключены или данные свежие:
  проверяйте состояние каждого источника.
- `meta.notice`: обязательное для интерфейса пояснение происхождения данных.
- `meta.timezone`: часовой пояс IANA; время отображается с учётом этого поля.
- `tasks[]`: идентификатор, название, курс, статус, приоритет, срок,
  приблизительные трудозатраты, материалы и подтверждающие фрагменты.
- `tasks[].due_at`: известный точный срок с часовым поясом.
- `tasks[].due_date`: дата без известного времени; взаимоисключающая с `due_at`.
  Если оба поля `null`, срок неизвестен. Фронтенд не подставляет 23:59.
- `tasks[].evidence[]`: `source_id`, название, цитата, необязательная ссылка
  и время публикации. Строки показываются как текст, не как HTML.
- `sources[]`: состояние `not_connected / connected / syncing / partial / error / stale`,
  описание, время последней успешной синхронизации и необязательная ошибка.
- `plan`: дата, доступные минуты, блоки с `task_id`, временем начала,
  длительностью и объяснением; задачи вне плана и общая заметка.
- `materials[]`: самостоятельные карточки материалов выбранной DSBA-группы:
  `id`, `title`, `course`, `source_id`, `url`, `fetched_at`. Без выбранной группы
  список пуст. Экран «Материалы» объединяет их со строками `tasks[].materials`;
  наличие задания для показа карточки не требуется. Ссылки ведут к источнику.

Поля `materials` сейчас содержат названия. Переход к объектам со ссылками
требует одновременного обновления схемы и интерфейса.

### Одинаковые имена для источников

`dashboard.sources[]` использует модель `Source`, а `GET /api/v1/sources` —
расширяющую её `SourceView`. Общие поля имеют одинаковые имена и значения:
`id`, `name`, `description`, `status`, `last_synced_at`, `error_message`.
Подписи, цвета и ошибки фронтенда не зависят от внутреннего устройства БД.

`SourceView` дополнительно возвращает `kind`, `base_url`, `document_count`,
`scope`, `last_run` и `last_error`. `last_error` сохраняется как технический код
для существующих клиентов; в интерфейсе показывается `error_message`.
`GET /api/v1/sources` содержит записи БД, а dashboard дополнительно показывает
неподключённые элементы каталога.

Стабильные ID каталога: `smartlms`, `mail`, `ruz`, `elk`, `telegram`, `wiki`.
Не подставлять отображаемое имя вместо `source_id`: доказательства связываются
с источником по ID. `task.id` и `plan.blocks[].task_id` также совпадают дословно.
В таблицах источников нет отдельной колонки description: её даёт общий каталог
`app/services/source_catalog.py`.

`partial` означает, что часть страниц получена, а часть недоступна. У него
собственные подпись и предупреждение, он не считается полным подключением.
Подписи всех состояний собраны в `frontend/static/js/source-status.js`;
неизвестное будущее состояние отображается без падения страницы.

Отметка «готово», правки длительности/приоритета и настройки пока сохраняются
только в localStorage этого браузера. Кнопка «Обновить план» повторно читает
dashboard; она не запускает парсинг и не пересчитывает персональный план.
`previous_due_at` / `previous_due_date` фронтенд читает опционально; бекенд пока
их не возвращает, переносы отслеживаются локально по изменению текущего срока.

### Ошибки и сценарии

Форма прикладной ошибки:

~~~json
{
  "error": {
    "code": "preview_unavailable",
    "message": "Пример ошибки загрузки. Попробуйте обновить страницу.",
    "retryable": true
  }
}
~~~

Для проверки состояний откройте:

- `/` — задания и подготовленный план с пометкой об учебных примерах;
- `/?scenario=empty` — пустые задания и план;
- `/?scenario=error` — HTTP 503, сообщение и повторная попытка;
- `/#tasks` и `/#sources` — отдельные представления.

Те же параметры доступны в `GET /api/v1/dashboard?scenario=...`.
Неизвестный сценарий возвращает стандартную ошибку валидации FastAPI (422).
При `HSE_DEMO_MODE=false` сценарии примеров возвращают 400; задания и план
остаются пустыми до персонализации. Статусы и сведения о библиотеке берутся из
БД, если она настроена. Успешный HTTP-ответ не означает подключение источника.

## Как работать параллельно

1. Фронтенд: `frontend/`; стили, адаптивность, детали задания, пустые состояния.
2. Коннекторы: `app/connectors/`; реальный доступ и нормализованные `SourceRecord`.
3. Извлечение и планирование: `app/services/`; общий формат
   `app/api/schemas.py`. OpenAI вызывается только на сервере.
4. Сервер, хранение, фоновые обновления и напоминания: отдельные модули
   внутри `app/`, которые переиспользуют сервисы.
5. Ресерч и защита: доступность источников, реальные примеры,
   сценарий демонстрации и список незавершённых интеграций.

Это предлагаемые границы файлов, а не назначение конкретных людей.
Изменения `schemas.py` согласуйте с фронтендом и обновите
снимок: `uv run python -m scripts.export_openapi`.
Проверка актуальности: `uv run python -m scripts.export_openapi --check`.

## Перед первым пушем

~~~sh
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run pytest
uv run python -m scripts.export_openapi --check
~~~

Проверьте браузер при узком и широком окне, фильтры, раскрытие источника,
навигацию, пустое состояние и ошибку. Не добавляйте в Git реальные письма,
выгрузки, токены, сессии и `.env`.

## DSBA Online

Подключение не требует заранее выбранной сервером группы: запросите
`GET /api/v1/integrations/dsba/catalog`, затем передайте выбранные
`program`, `year`, `group`, `sub`, `subjects` в
`POST /api/v1/integrations/dsba/sync`.
Ответный `source_id` сохраняется во фронтенде и передаётся как
`dsba_source_id` в dashboard и `source_id` в documents.
Без него dashboard не смешивает задания подключённых учебных групп.
Авторизация пользователя будет добавлена отдельно; `source_id` не является
токеном доступа. Сейчас читаются только публичные данные.
Полный контракт, ошибки и автоматическое обновление: [DSBA.md](DSBA.md).
