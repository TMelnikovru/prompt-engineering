# Первая интеграция: вики ФКН

Официальный источник — https://wiki.cs.hse.ru/api.php.
Коннектор использует MediaWiki Action API: `action=parse`, `formatversion=2`,
`prop=text|links|revid|displaytitle`, `redirects=1`, `maxlag=5`.
Адрес, формат ответа и открытый доступ проверены на настоящей вики.
Предоставленные Orbit REST endpoints для Wikipedia не покрывают этот сайт;
контракт сверялся с [MediaWiki](https://www.mediawiki.org/wiki/API:Parsing_wikitext).

## Схема хранения

| Таблица | Что хранится |
| --- | --- |
| ingestion_sources | Тип источника, адрес, границы обхода, последнее успешное обновление |
| source_documents | Устойчивая идентичность страницы: источник + внешний pageid, название, URL |
| document_versions | HTML, очищенный текст, ссылки, ревизия и хеш содержимого |
| ingestion_runs | Запуски синхронизации, счётчики, ошибки и фактический объём обхода |
| ai_artifacts | Результаты извлечения и сводки, модель, версия промпта, входные версии и токены |

Идентичность документа не зависит от названия страницы. Уникальны пары
`source_id + external_id` и `document_id + revision_key`.
У документа есть указатель на текущую версию; предыдущие версии сохраняются.
Хеш нормализованного содержимого позволяет повторно использовать ИИ-результат
при новой ревизии с тем же текстом. Advisory locks исключают параллельный
запуск одного sync и двойную оплату одинакового анализа.
Для locks используются отдельные непулируемые соединения; они освобождаются
даже при завершении процесса и не занимают пул прикладных сессий.

Для Telegram позже можно использовать ту же структуру: источник — чат/канал,
external_id — ID сообщения, версия — изменение текста. Приватные источники
потребуют авторизации и связи с владельцем; текущие HTTP read endpoints
предназначены для публичной вики.

## Запуск

~~~sh
uv sync --frozen
uv run alembic upgrade head
uv run python -m app.ingest sync-wiki
uv run python -m app.ingest analyze --limit 5
uv run python -m app.ingest summarize --limit 20
~~~

По умолчанию: главная страница и связанные с ней статьи основного namespace,
до 25 страниц, глубина 1, пауза между страницами 0.25 секунды. Это ограниченный
набор, а не копия всей вики. `has_more` указывает остаток очереди в текущей глубине.
Параметры: `--seed "Название курса"` (можно несколько), `--max-pages 100`,
`--depth 2`. В окружении те же настройки: `HSE_WIKI_SEEDS` (JSON-массив),
`HSE_WIKI_MAX_PAGES`, `HSE_WIKI_MAX_DEPTH`, `HSE_WIKI_API_URL`.

При ошибке уже загруженные страницы сохраняются. Старые материалы не удаляются
из-за недоступности источника; в статусе будет error или stale.
Неполный запуск записывается как partial/failed, прерванный — interrupted.

## Два ИИ-этапа

HTTP-загрузка и очистка HTML не расходуют токены OpenAI.
Первый этап — структурированное извлечение из новых/изменённых документов:
`HSE_EXTRACTION_MODEL`, по умолчанию `gpt-6-luna`.
`OPENAI_MODEL` поддерживается как прежнее имя настройки первого этапа.
Второй этап — сводка по уже извлечённым данным: `HSE_SUMMARY_MODEL`,
по умолчанию `gpt-6.1-sol`. Более дорогая модель получает компактные результаты.
Модели заменяются конфигурацией. Документация:
[Luna](https://developers.openai.com/api/docs/models/gpt-6-luna),
[Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol),
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

Ключ — только серверный `OPENAI_API_KEY`. Requests используют Responses API
со строгой JSON Schema, `store=false`, таймаутом и ограничением output tokens.
Результат кешируется по содержимому, модели и версии промпта; расход токенов
сохраняется. Без ключа загрузка вики работает, ИИ возвращает openai_not_configured.

Текст разбивается на блоки по 12000 символов с перекрытием 300; максимум 8 блоков.
При ограничении охвата результат содержит coverage=partial.
Цитаты должны присутствовать в переданном тексте, due_text — внутри цитаты.
Год, время и дедлайн не вычисляются моделью. Извлечённые задания остаются
кандидатами: публичные страницы относятся к разным курсам и годам, поэтому
они пока не попадают в персональный план автоматически.

## API для фронтенда

- GET /api/v1/sources — состояние, число документов, последний запуск и границы обхода.
- GET /api/v1/documents?source_id=wiki&limit=20&offset=0 — список материалов.
- GET /api/v1/documents/{id} — текст, версия, ссылки, история в виде version_count и анализ.
- GET /api/v1/knowledge/summary — последняя сохранённая сводка; чтение не вызывает модель.
- POST /api/v1/integrations/wiki/sync — операторский запуск, только с
  X-Ingestion-Token, совпадающим с HSE_INGESTION_TOKEN. Без настройки отключён.
  Конкурирующий запуск — 409, полный отказ источника — 502 с отчётом запуска.

Полный контракт: /docs и docs/openapi.json. Источник wiki в dashboard отображает
реальный статус БД, остальные источники остаются неподключёнными.

## Периодическое обновление

### Отдельный коллектор при сетевых ограничениях

Из серверной сети docker-prod запросы к вики завершаются таймаутом, хотя
с рабочей машины тот же официальный API доступен. Для этого поддерживается
отдельный коллектор: он скачивает настоящие страницы, сохраняя pageid,
ревизии, URL и fetched_at, и передаёт batch по SSH в серверный import-wiki.
Обхода авторизации нет: читаются те же публичные страницы.
Результат в БД помечен scope.transport=collector.

~~~sh
uv run python -m app.collector --once --max-pages 5
uv run python -m app.collector --max-pages 25
uv run python -m app.collector --max-pages 25 --analyze --analyze-limit 5
~~~

По умолчанию target — SSH host docker-prod, root — каталог PostgreSQL preview.
Коллектору нужен SSH-доступ, но не ключ OpenAI. Команда без --once повторяется
каждые 900 секунд; рабочая машина должна оставаться включённой и иметь доступ
к источнику. Если обновлений нет больше двух интервалов, источник становится stale.
Серверный ключ и ИИ-обработка остаются внутри preview. Для полностью автономного
серверного worker потребуется исправить исходящий сетевой доступ к wiki.cs.hse.ru.

`uv run python -m app.ingest worker --analyze --limit 5` — цикл с интервалом
HSE_WIKI_INTERVAL_SECONDS (по умолчанию 900 секунд), для запуска под supervisor.
Сводка дорогой моделью запускается отдельно, автоматической платной сводки нет.

Для существующего preview предусмотрен `deploy/sync-wiki.sh`: он выполняет
один sync и обрабатывает до пяти ещё не разобранных документов. Его можно
вызывать cron каждые 15 минут с каталогом preview первым аргументом.
Он использует текущую версию контейнера и серверный .env, защищён flock.

## Проверка

Локально HTTP-клиенты проверяются через настоящие соединения к stand-in
MediaWiki/OpenAI. Postman simulation: `postman simulation run
postman/simulations/wiki-ingestion.sim.yaml --port 4910`.
Контекст воспроизведения — рядом с sim.yaml.
В CI с PostgreSQL проверяются версии, повторная загрузка, кеш, отказ внешнего
сервиса, точность цитат, API и сохранность уже принятых данных.
